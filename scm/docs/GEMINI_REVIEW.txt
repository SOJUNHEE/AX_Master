Gemini 검수 요청서 — Flow SCM
========================================

아래 프로젝트를 SCM 실무, Python/Flask, UI 디자인, 접근성 및 웹 배포 관점에서 검수해 주세요.
검수 결과는 실제 파일·코드·실행 화면을 근거로 작성하고, 문제마다 재현 단계, 영향, 수정 방법, 우선순위를 알려 주세요.

1. 사용자 요청
----------------------------------------
- https://godly.design/website/taito/ 를 참고한 SCM 대시보드.
- Flask 사용 및 Render 배포 준비.
- 처음 보는 사람도 이해하기 쉬운 용어와 화면. 전문가용으로 지나치게 복잡하지 않을 것.
- 한글 글꼴이 깨지지 않고 색상 대비와 가독성이 좋을 것.
- PC/모바일 반응형, 카테고리 분류, 클릭 반응, 동적인 차트.
- macOS 느낌 및 사용자 이미지 파일 활용.
- 용어 위에 마우스를 올리면 뜻 표시. 모바일 터치와 키보드로도 이용 가능할 것.
- 챗봇을 제공하되 사용자가 자기 API 키를 입력할 것.

2. 현재 구현
----------------------------------------
이름: Flow SCM / 흐름이 보이는 업무 공간.
기술: Python Flask, Jinja2, CSS, 순수 JavaScript, SVG 차트. 별도의 JS 빌드 과정 없음.
디자인: 크림/세이지 배경, 짙은 녹색 텍스트·버튼, 카드와 넉넉한 여백, 친근한 문구.
서체: Pretendard Variable을 프로젝트에서 직접 제공. 한글 시스템 글꼴 fallback.
이미지: CSS로 만든 상자·macOS 느낌 폴더, 직접 만든 SVG 아이콘. Apple 원본 자산은 포함하지 않음.

화면: 한눈에 보기 / 주문 관리 / 재고 관리 / 배송 현황 / 거래처 / 보고서 / 이미지 보관함 / AI 도우미.
전역 필터: 7/14/30일, 3개 센터, 디지털/리빙/패션 카테고리.
목록: 검색, 상태별 필터, 10개 단위 페이지 이동, 상세 dialog, 빈 결과 처리.
대시보드: 4개 지표, 주문/출고 흐름·막대 전환, 배송 상태 도넛, 체크 포인트, 최근 주문.
보고서: 현재 전역 필터에 대응하는 전체 주문 CSV. UTF-8 BOM 포함. 브라우저 인쇄/PDF 지원.
용어: SCM, 안전재고, OTD, 출고, SKU, 리드타임, 주문금액, 현재고 사전 및 툴팁.
테마: 세이지/오션/샌드. 이미지 배경 설정은 첫 화면의 소개 카드에 적용.

3. 데이터의 의미 — 이 부분을 특히 검수해 주세요
----------------------------------------
실제 ERP나 WMS에 연결되지 않은 데모입니다. 180건의 주문, 8종 상품, 3개 물류센터, 4개 거래처를 고정 규칙으로 생성합니다.
주문번호·상품·거래처·센터·수량·금액·날짜·상태를 포함합니다.
- 접수된 주문: 전역 필터에 맞는 주문 건수.
- 현재고: 선택한 센터/카테고리의 현재 보관 수량 합계. 기간 필터는 재고에 영향을 주지 않음.
- 재고 부족: 현재고가 설정 안전재고보다 작은 상품/센터 항목의 수.
- 정시 배송률(OTD): 배송 완료 주문 중 on_time=True인 주문 수 / 배송 완료 주문 수 × 100. 완료 주문이 없으면 null/—.
- 주문금액: 모든 상태의 주문 수량 × 단가 합계. 확정 매출이 아님을 표시.
- 출고 수량: 배송 중 및 배송 완료 주문의 수량 합계. 차트 날짜는 주문일 기준으로 묶은 수량이며 실제 출고 발생일 시계열은 아님.
- 지연: 현재 상태가 지연인 주문 수. 배송 완료되었지만 늦었던 주문은 OTD에 반영되나 현재 지연 건수에는 포함하지 않음.

거래처·차트·CSV·챗봇 컨텍스트 간 숫자 일치와 빈 분모 처리를 확인해 주세요.

4. 이미지 및 저장
----------------------------------------
PNG/JPG/WebP, 파일당 5MB, 4,000만 화소 이하. createImageBitmap으로 디코딩 확인.
이미지는 브라우저 IndexedDB에 저장하며 서버에 업로드하지 않습니다. 미리보기/배경/삭제 지원.
테마와 배경 ID는 localStorage에 저장합니다. 이미지 object URL은 교체·삭제 시 해제합니다.
브라우저 데이터를 삭제하거나 다른 기기로 이동하면 동일한 보관함을 볼 수 없습니다.
이는 개인 화면 설정이며 팀 공유 파일 저장소가 아닙니다.

5. 챗봇
----------------------------------------
공급자: Google Gemini REST generateContent. 모델 ID는 사용자가 변경 가능. 기본 문자열 gemini-2.5-flash.
Gemini API 키는 현재 페이지 메모리 및 password 입력칸에만 유지하고, 새로고침/키 지우기로 삭제.
서버 세션에는 CSRF 토큰만 존재. 서버 DB·localStorage·URL에 키 저장하지 않음.
API 키는 요청 본문으로 Flask에 전달하고, 고정 Google 도메인의 x-goog-api-key 헤더로 전송.
임의 API URL을 입력받지 않음. 모델 ID의 문자 범위 검증.
최근 최대 6개 메시지, 현재 필터의 데모 metrics 및 거래처 요약을 AI에 전달.
질문 2,000자, 요청 본문 32KiB 제한. 제공자 연결/읽기 timeout, 비정상 응답, 인증/한도/모델 오류 처리.
사용자 및 모델 답변은 textContent로 렌더링. HTML 실행하지 않음.
API 사용료 및 Google 전송을 UI에 설명. 키를 입력해도 실제 연결 확인은 질문 전송 시 이뤄짐.
실제 유료 API 키로 원격 요청을 실행하지 않았습니다. 서버 요청 모의 응답과 브라우저 응답 가로채기로 성공·실패 흐름을 검증했습니다.

6. 배포
----------------------------------------
render.yaml: Python, python -m gunicorn app:app, PORT 바인딩, 1 worker/4 threads, timeout 60, /healthz, 자동 SECRET_KEY 생성.
현재 상위 저장소 안 scm 폴더 구조에 맞게 rootDir: scm 지정.
독립 저장소 루트가 scm의 내용이라면 rootDir 줄을 제거해야 함.
여러 worker에서 SECRET_KEY가 같아야 하므로 Render 환경 변수 필수.
Render HTTPS에서 secure session cookie. SameSite=Lax, HttpOnly, CSRF 검증.
응답 보안 헤더: CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, 데이터 no-store.
실제 Render 서비스 생성/공개 배포는 아직 하지 않았습니다.

8. 검증 범위 및 남은 한계
----------------------------------------
서버 테스트: 기본 경로·자산, 필터별 집계, 현재고 기간 독립성, 잘못된 필터, 한글 CSV, CSRF, 입력 검증, 모의 Gemini 성공, 오류 코드별 비밀정보 비노출, timeout, 본문 제한.
브라우저: PC, 360/390/768/1024px 반응형, 검색/상세/빈 결과/재고 필터/차트 모드, CSV 실제 다운로드, 이미지 선택/배경/새로고침 유지/삭제, 테마, 모의 AI 답변, 키의 localStorage 비저장 및 새로고침 제거. JS 실행 오류 없음.
실제 iPhone/Safari 및 유료 Gemini 연결은 미검증.
현재 로그인, 팀 권한, 영구 기업 DB, ERP/WMS, 실제 발주·배송 변경, 팀 이미지 공유는 구현 범위에 없음. 실서비스 데이터 연결 전 별도로 추가 필요.
서버 측 분산 사용량 제한도 미구현. 공개 데모에서는 사용자가 자기 키를 사용하는 형태.

9. 원하는 검수 결과
----------------------------------------
A. 긴급/중요/개선으로 나눈 실제 문제 목록(파일 위치와 재현 단계 포함).
B. 모바일에서 글씨·버튼 크기, 가로 넘침, 메뉴, 툴팁, dialog, 화면 확대 확인.
C. 키보드 접근, 포커스, 색상 대비, 스크린리더 이름, reduced-motion 점검.
D. SCM 지표가 과장되거나 실제 데이터처럼 오인되는 문구 확인.
E. CSV 집계와 날짜 기준, 차트 수량·OTD 분모 검증.
F. API 키와 사용자의 입력·이미지 처리에서 데이터 유출/XSS/CSRF 가능성 확인.
G. Render의 rootDir, 환경 변수, Gunicorn worker, 첫 요청·재시작 시 동작 확인.
H. 현 범위를 유지하면서 초보자에게 더 쉬워지는 UI 개선 5가지.

중요: 모든 제안은 실제로 구현된 동작을 확인하고 작성해 주세요. 데모라는 이유만으로 존재하지 않는 실데이터 기능이 있다고 가정하지 말아 주세요.
